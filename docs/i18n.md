# Internationalization

The app ships English and Japanese with equal coverage.
Switching language is a display-only change: it never touches the game state.


## Setup

`src/i18n/index.ts` exports `createAppI18n(locale)`, which calls Vue I18n's `createI18n` in Composition API mode (`legacy: false`) with English as the fallback locale.
`src/main.ts` creates the instance with the result of `resolveInitialLocale(storage, navigator)` before mounting the app.


## Initial locale

`resolveInitialLocale` applies two rules in order:

1. A saved preference under `tcdb:preferences` wins.
2. Otherwise `detectLocale` scans `navigator.languages` (falling back to `navigator.language`).
   The first tag starting with `ja` selects Japanese, the first tag starting with `en` selects English, and anything else falls back to English.

A corrupted or unknown preference is ignored, not treated as an error.


## Switching and persistence

`useLocale()` in `src/composables/useLocale.ts` exposes the current locale, `setLocale`, and `toggleLocale`.
`setLocale` changes the Vue I18n locale and writes the preference.
The preference is written only on an explicit choice.
A locale that was merely detected from the browser is not saved, so a user who later changes their browser language still gets the new detection.

`useLocaleSideEffects()` runs once from `App.vue` and keeps `<html lang>` and `document.title` in sync.

`LanguageSwitcher.vue` renders `English | 日本語` as a `role="group"` of toggle buttons with `aria-pressed`, and sets `lang` on each button so screen readers pronounce the labels correctly.


## Message catalogues

* `src/i18n/locales/en.ts` is the schema source: a plain object export.
* `src/types/i18n.ts` derives `MessageSchema` from it with `typeof en`.
* `src/i18n/locales/ja.ts` is typed as `MessageSchema`, so a missing or extra key fails `pnpm typecheck`.
* `src/tests/i18n.test.ts` also checks key parity in both directions and that no message is empty.

Messages use named interpolation (`{current}`, `{total}`) and pipe-separated plural forms for `game.remaining`.
Keys are grouped by screen: `app`, `welcome`, `game`, `results`, `cell`, and `errors`.


## Question text

Question text does not live in the catalogues.
`src/data/questions.ts` holds each question once with an `id` and a `text` object keyed by locale:

```ts
{ id: 'q02', text: { en: 'Paid for the whole date', ja: 'デート代を全額払った' } }
```

`getQuestionText(id, locale)` returns the text for the locale, falls back to English, and finally to the ID itself.
Components call it at render time, so the current card, the board cells, the detail dialog, and the export all follow the active locale.


## Why switching never breaks a game

The store, the storage format, and the Bingo engine use question IDs only.
When the locale changes:

* The shuffled order is unchanged, so the player stays on the same card number.
* The answers are unchanged, because they are keyed by ID.
* The board arrangement is unchanged, because it is a list of IDs.
* The deck re-renders the same card keys with new text; no swipe is triggered.

The integration tests in `src/tests/i18n.test.ts` switch language on the welcome, swipe, and results screens and assert that the saved JSON is byte-for-byte identical before and after.


## Adding a language

1. Add the code to `Locale` and `LOCALES` in `src/types/game.ts`.
2. Add `text.<code>` to every question in `src/data/questions.ts`; TypeScript flags any that are missing.
3. Create `src/i18n/locales/<code>.ts` typed as `MessageSchema` and register it in `messages` in `src/i18n/index.ts`.
4. Extend `detectLocale` if browser detection should select it.
5. Add an option to `LanguageSwitcher.vue`.
6. Run `pnpm typecheck` and `pnpm test`.


## Typography

The body font stack starts with Noto Sans JP from Google Fonts, then Hiragino Sans, Yu Gothic, Meiryo, and the system UI font, so Japanese renders correctly even when the web font fails.
Cards and cells use `line-break: strict` and `overflow-wrap: anywhere` so long Japanese labels wrap instead of overflowing.
The script title font (Pacifico) is only used for the Latin brand name.
